# Проверки и диагностика

## Локальные команды

Из корня репозитория бэкенда (Python 3.12):

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r backend/requirements-dev.txt
python -m pytest backend/tests -q
git clone https://github.com/mitetenov/remnawave-dns-guard-agent.git agent
python -m pip install -r agent/requirements.txt
python -m pytest integration_tests -q
```

Backend-тесты используют временную SQLite и имитированные API. Агент-тесты используют контролируемые ответы HTTP/Xray; реальные секреты не нужны. Проверяется автоматический переход ошибка/восстановление, защита последнего A, ручное отключение, недоступная контрольная связь, replay и валидация адаптеров/профилей в пределах набора тестов. Точное покрытие и имена сценариев смотрите в `backend/tests` и `agent/tests`.

```sh
docker compose config --quiet
docker build -t remnawave-dns-guard-backend:local .
python3 scripts/smoke_image.py remnawave-dns-guard-backend:local
```

`config --quiet` проверяет Compose без печати подставленных секретов. Обычный `docker compose config` раскрывает секреты — не публикуйте его вывод. Compose запускает опубликованные образы, а локальная сборка выполняется явно через `docker build`. Тесты агента и фронтенда выполняются в их самостоятельных репозиториях; команды приведены в соответствующих README.

В каждом из трёх репозиториев свой GitHub Actions CI. Backend выполняет Python-тесты и agent→backend цикл с реальной временной SQLite и имитированным Cloudflare, проверяет Compose и запущенный Docker-образ (health, вход, poll агента, UID, сохранение сессии после restart, SQLite integrity). Агент выполняет unit-тесты, проверку Compose и разбор десяти профилей настоящим Xray из образа без сети. Frontend выполняет Vitest и TypeScript/Vite build, проверяет запущенный nginx и его проксирование на тестовый upstream. После успешных проверок `main` публикует соответствующий AMD64-образ с тегами `latest` и `sha-<полный commit SHA>` в Docker Hub. Pull request не публикует образы. Для публикации нужен `DOCKERHUB_TOKEN`; тесты и сборки работают без него. Deploy не выполняется. Frontend build и nginx smoke-тест не заменяют проверку поведения UI в браузере.

## Границы проверки

Для локальных image smoke-тестов нужен работающий Docker Engine. Фактический статус локальных проверок, GitHub CI и публикации образов проверяется отдельно; наличие workflow само по себе не доказывает успешный запуск или публикацию.

Без настоящих токенов, RU-хоста и VLESS inbound не проверяются живые Cloudflare/Remnawave, реальный Xray handshake, блокировки провайдера, DNS propagation и публичный TLS reverse proxy. Никакие live DNS-записи в процессе разработки не меняются. Перед включением автоматики на рабочем hostname используйте отдельный тестовый пул с минимум двумя DNS-only A, оставьте автоматику выключенной, проверьте все адреса через RU-агент, затем проверьте исключение и восстановление на тестовом узле.

## Частые причины отказа

| Симптом | Что проверить |
| --- | --- |
| Compose сообщает обязательную переменную | Файл `.env` в корне соответствующего репозитория, заполненные обязательные поля |
| Backend не запускается | Длина/наличие секретов, валидный `PUBLIC_ORIGIN`, права UID 10001 на `/data`, сообщения запуска без публикации секретов |
| Login/изменения дают 403 | Origin браузера точно совпадает с `PUBLIC_ORIGIN`, secure Cookie используется через HTTPS, proxy сохраняет заголовки |
| Зоны Cloudflare не видны | Токен `Zone Read` + `DNS Edit`, ресурс ограничен нужной зоной, зона доступна владельцу токена |
| Remnawave 401/403 | HTTPS URL панели, API token и scopes list/read для nodes/hosts; proxy не подменяет Authorization |
| Агент не виден | Совпадающий токен, корректный HTTPS URL, исходящий доступ, отсутствие интерактивного login на `/api/agent/` |
| Агент виден, проверки не идут | Прямая контрольная связь здорова, цели включены, профиль сохранён, срок очередного интервала |
| Все цели ошибочны, control здоров | Проверка общего VLESS профиля: UUID/порт/SNI/REALITY key/flow/transport; реальные ответы PROBE_URLS |
| Адрес protected | Это последний фактический A; добавьте и проверьте другой работоспособный адрес |
| Исключённый IP не вернулся | Автоматика включена, цель не отключена вручную, достигнут порог последовательных успехов, Cloudflare доступен |
| Docker unhealthy не перезапускается | Это поведение Docker: restart применяется при завершении процесса, сначала устраните причину healthcheck |

Логи контейнеров и UI журнал показывают ошибки без токенов/URI. При обращении за помощью передавайте обезличенные статусы и версии, не `.env`, SQLite, полные VLESS URI или Xray-конфиги.
